1 프로젝트 개요
1.1 개발 배경
부산 지역의 주차장 정보는 제공기관과 데이터셋에 따라 분산되어 있어, 이용자가 목적지 주변 주차장의 위치·요금·운영시간·실시간 주차 가능 여부를 한 번에 비교하기 어렵다. 본 프로젝트는 공공 주차장 데이터, 지도 서비스 및 LLM을 연계하여 주차장 탐색 과정을 단순화하는 모바일 앱 서비스를 개발한다.
1.2 개발 목적
사용자가 “서면역 근처에서 2시간 주차하고 5천 원 이하인 곳”처럼 자연어로 조건을 입력하면, 시스템이 목적지·주차 예정 시간·예산을 구조화하고 실제 조회된 주차장 데이터를 기반으로 검색·요금 계산·추천 결과를 제공하도록 한다.
1.3 대상 사용자 및 운영 형태
• 부산 지역 방문객과 운전자: 주차장 탐색, 예상 요금 비교, 위치 확인
• 설치형 모바일 앱을 개발한다. 제안 환경은 React Native·Expo이며 Android 우선 시연, iOS 확장은 추후 검토한다. 대상 OS·최소 지원 버전·실제 사용 기기는 1주차에 팀에서 확정한다.
• 일반 사용자는 회원가입 없이 검색하며, 관리자 데이터 상태 화면은 별도 인증을 적용한다.
2 목표 및 개발 범위
2.1 필수 구현 목표 Must
• 자연어 입력·LLM 조건 추출·조건 수정 (FR-001~003)
• 부산 목적지 좌표 조회 및 반경 2km 주차장 검색 (FR-004~005)
• 주차장 목록·상세정보·예상 요금 제공 (FR-006~008)
• 예산 필터·누락 정보 처리·거리 우선 추천 (FR-009, FR-011~012)
• 제공되는 경우 실시간 주차 가능 대수와 갱신 시각 표시 (FR-010)
• 지도 마커, 검색 결과 없음 및 API 오류 처리 (FR-014, FR-016~018)
2.2 추가 구현 범위 및 Should 목표
• 실제 조회 수치를 근거로 한 AI 추천 이유 생성 (FR-013)
• 외부 지도 서비스 길찾기 연결 (FR-015)
• 안내판 이미지 해석은 SRS 범위 및 UC-002에 포함된 기능으로 개발한다. 실패·타임아웃 처리와 개인정보 보호는 AI-REQ-02·03의 Must 항목이며, 불확실한 추출값 표시 기준은 AI-REQ-06의 Should 항목이다.
• 관리자 데이터 적재 상태 조회(UC-006)를 포함한다. Supabase Auth 기반 팀원 인증 후 적재 시각·건수·API 상태를 확인하며, 적재는 담당자의 로컬 스크립트로 수행한다.
2.3 제외 범위
실제 주차 예약·결제, 일반 사용자 회원 계정 관리, 실시간 정보가 없는 주차장의 잔여 면수 추정은 제외한다. 모바일 앱 빌드와 Android APK 시연 배포는 포함하며, 정식 스토어 출시와 iOS 배포는 초기 필수 범위가 아니다. 관리자 인증은 별도 구현한다.

3.1 추천 규칙
직선거리 2km 이내 후보에서 유효한 실시간 정보로 만차가 확인된 주차장을 제외하고, 예산이 있으면 계산 가능한 요금이 예산 이하인 후보만 추천한다. 계산 불가 후보는 별도 확인 목록으로 구분한다. 예산이 없으면 계산 불가 후보도 포함하되 동일 거리에서는 확인된 요금을 우선한다. 거리 → 요금 → 내부 ID 순으로 정렬하며 상위 5개와 전체 목록을 제공한다. 면수 미제공·오류·오래된 정보는 확인 불가 또는 자리 확인 필요로 표시한다. 
(FR-005, FR-008~012)
요금 계산은 SDD 5.4의 기본·추가·일 최대요금 규칙을 따른다. 기본 시간 전후와 추가 단위 경계를 테스트하고, 무료는 0원, 누락 정보는 계산 불가로 구분한다. 시간대별·할인·1일 초과 등 초기 지원 범위 밖 정책은 추정하지 않는다.
3.2 AI 처리 흐름
개인정보 마스킹 → 자연어 조건 추출 → JSON 검증 → 사용자 확인·수정 → 실제 목적지·주차장 데이터 조회 → 코드 기반 요금 계산·필터·정렬 → 근거 설명의 순서로 구현한다. JSON 스키마 위반 시 전체 5초 제한 안에서 1회 재시도하고, 다시 실패하거나 시간이 부족하면 수동 입력 폼으로 전환한다. 규칙 기반 파서로 자동 대체하지 않는다. 추천 설명은 결과 목록 표시 후 별도로 요청하며 실패 시 정형 문구로 대체한다. (FR-018, AI-REQ-01,05,07)
안내판 이미지 해석은 별도 VLM API로 구현한다. 불확실한 값은 null 및 확인 필요로 표시하고, 15초 제한시간 또는 분석 실패 시 다시 업로드를 안내한다. 추출값은 참고 정보로 제시하고 공식 DB 요금 정책을 자동 수정하지 않는다. (UC-002, AI-REQ-02,06)

4.1 데이터 확보 및 통합 계획
DATA-01은 공공데이터포털 전국 주차장 정보표준 데이터 중 부산 공영주차장을 정제하여 적재한다. DATA-02는 부산시설공단 실시간 API, DATA-03은 카카오맵, DATA-04는 사용자가 업로드한 안내판 이미지이다. 추가 데이터는 필요 시 별도 검토하며 부산관광공사 자료를 필수 출처로 전제하지 않는다. 주차장 명칭·주소·좌표를 대조하고 담당자가 확인한 외부 ID 매핑만 실시간 조회에 사용한다.
정적 데이터는 초기 적재 후 주 1회 갱신 여부를 점검하고, 원본 변경 시 재적재한다. DB는 parking_lots·fee_policies·source_mappings·import_runs로 구성한다. 실시간 캐시 TTL 30초와 호출 제한시간 1.5초를 초기값으로 적용한다. 기관 갱신 시각과 서버 조회 시각을 분리하고, 기관 시각 누락이나 5분 이상 지난 정보는 확정적인 빈자리·만차 판단에 사용하지 않는다. 실제 갱신 주기 확인 후 기준을 조정한다.
4.2 보안 개인정보 계획
OpenAI·공공데이터·카카오 REST 비밀 키와 Supabase service_role 키는 서버에만 둔다. APK·앱 코드·앱 공개 환경변수에 비밀 키를 포함하지 않는다. 지도 표시용 공개 키는 앱 패키지명·서명 등 제공자가 지원하는 제한을 적용한다. DB에는 RLS, 관리자 API에는 액세스 토큰 검증과 권한 검사를 적용한다. 질의 개인정보는 서버가 외부 AI 전송 전에 마스킹한다. (NFR-004, AI-REQ-03)
앱의 시스템 사진 선택기로 안내판 사진을 선택하고, 카메라 촬영을 사용할 때만 촬영 권한을 요청한다. 자르기·가리기 UI와 외부 전송 전 OCR 개인정보 검사를 적용하고 검사 실패 시 전송을 차단한다. 형식·크기를 검증하고 EXIF를 제거한다. 이미지는 DB·공개 스토리지에 저장하지 않으며 처리 후 앱 임시 파일과 서버 참조를 정리한다. 초기 제한은 JPG·PNG, 5MB, 가로·세로 각 4,096px로 두고 API 서버 제한에 맞춘다.
앱은 목적지를 직접 입력하는 경로를 기본 제공한다. 현재 위치를 추가 사용할 경우 사용 직전에 위치 권한을 요청하며, 권한 거부 시 수동 검색이 계속 동작해야 한다. 관리자 로그인 토큰은 OS 보안 저장소에 보관하고 로그아웃 시 삭제한다. 앱이 백그라운드에서 복귀하면 표시된 갱신 시각을 확인하고 필요 시 재조회한다. 네트워크 끊김·화면 뒤로가기·중복 요청은 취소와 다시 시도 안내로 처리한다.
5 개발 방법과 협업 체계
5.1 구현 전략
정적 데이터·수동 조건 검색·요금·추천·지도·상세를 먼저 구현하고, 실시간 데이터와 예외 처리, 자연어 분석·설명, 이미지 해석·관리자 상태 순으로 통합한다. 외부 API 접근과 이미지 OCR 배포 가능성은 개발 초기에 확인한다. Must 기준을 우선 검증하며 Should 기능은 핵심 기능 안정화 후 추가하되, 이미지 관련 Must 기준을 선택 사항으로 낮추지 않는다.
5.2 협업 규칙
• GitHub 기능별 브랜치에서 작업 후 Pull Request로 통합
• API 요청·응답 형식과 DB 스키마를 초기에 합의
• 주 2회 이상 진행 상황 공유 및 기능별 완료 조건 확인
• 외부 API 키·환경변수는 예제 파일로 공유하되 실제 비밀값은 저장소에 업로드하지 않음
• 변경되는 요구사항은 SRS·SDD·개발 계획서에 함께 반영
• 앱 클라이언트와 API 서버는 같은 저장소의 mobile/·server/로 구분하고, shared/에서 요청·응답 타입을 공유
6 단계별 일정 및 마일스톤
기존 계획의 문서 준비 목표일 2026-10-25와 구현 4주안을 유지하되, 공식 제출일·개발 시작일은 확인 전이다. 문서 준비 기간과 구현 1~4주차는 별도 구간이며 4주는 구현 착수 후의 제안 기간이다. 5명의 역할 분담과 기능별 병행 개발을 전제로 하며, 1주차 검토에서 실제 작업량과 공식 마감일에 맞춰 조정한다.

8.1 기능 인수 시험
SRS의 AC-001~AC-018과 SDD 12장의 TC-F001~018, TC-N001~008, TC-A01~07 및 TC-U006을 검증 계획에 연결한다. 이미지·관리자 기능은 AC-001~018에 별도 항목이 없으므로 UC-002·006 및 AI 요구사항으로 검증한다. 모든 결과는 통과·실패·재시험으로 기록하며, 아직 검증된 것으로 표시하지 않는다.

8.2 테스트 유형
단위 테스트는 2km·요금·예산·만차·동률·누락 경계를 확인한다. 통합 테스트는 앱→API 서버→DB·외부 서비스 경로를 검증한다. 앱 테스트는 터치·키보드·뒤로가기·화면 크기·권한 거부·사진 선택·오프라인·백그라운드 복귀·길찾기 앱 미설치를 포함한다. 에뮬레이터와 실제 Android 기기에서 설치형 APK를 실행하고, iOS는 지원 범위로 확정된 경우 검증한다. 외부 장애는 모의 테스트 후 실제 값과 대조한다.
8.3 완료 판정
Must 기능·AI·NFR 기준과 해당 인수 시험 결과를 확인하고, Should 항목의 달성 여부도 별도 기록한다. 실시간 정보는 실제 제공 범위 안에서 검증한다. 데이터 미확보나 일정 지연으로 요구사항 변경이 필요하면 팀 검토와 수업 기준 확인 후 SRS·SDD·계획서에 함께 기록한다. 모의 테스트만 통과한 기능을 실제 API 연동 완료로 표시하지 않는다.

• 프로젝트 개발 계획서 및 발표자료
• 부산 주차장 데이터베이스·정제 규칙·데이터 출처 기록
• 모바일 앱 및 API 서버 소스 코드, Android APK, 설치·실행·서버 배포 안내
• 테스트 케이스, AI 평가 결과 및 인수 시험 기록
• 최종 시연 화면 또는 시연 영상
10.2 계획 확정 전 확인 사항
• 실시간 주차정보 API의 실제 제공기관·접근권한·갱신 주기 확인
• DATA-01~04의 실제 필드·형식·출처·갱신 조건과 데이터셋 간 외부 ID 매핑 확인
• UC-002 이미지 처리와 UC-006 관리자 조회의 상세 흐름 보완, OCR 개인정보 필터·배포 가능성 검증
• 자연어 실패는 직접 입력(FR-018·AI-REQ-07), 이미지 실패는 다시 업로드(AI-REQ-02)로 구분하여 검증
• Expo 빌드 환경·Android 서명 및 APK 설치, API 서버·Supabase·외부 서비스 호출량과 제한 확인
• SDD 요금 계산 지원 범위 확인, 운영시간은 제공 정보 표시로 구현하며 별도 필터는 범위 변경 시 합의
2026년 10월 9일 최신 첨부본을 모바일 앱 기준으로 수정하였다. React Native·Expo와 Android 우선 시연은 제안이다. SRS의 운영 환경·앱 배포 제외·지도 표시 방식은 앱 기준으로 개정하고, 요구사항 ID와 검색·요금·추천 기준은 유지한다.
