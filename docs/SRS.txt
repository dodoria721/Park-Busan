1. 문서 개요 (Introduction)
1.1 목적 (Purpose)
본 문서는 AI 기반 부산 주차장 추천 서비스 ‘파크부산(ParkBusan)‘이 만족해야 할 요구사항을 정의한다.본 문서는 시스템 아키텍처, 컴포넌트 설계 등의 작성의 기준이 된다.대상 독자는 다음과 같다.· 개발팀원 — 설계 및 구현 범위의 기준으로 사용· 담당교수 및 평가자 — 과제 요구 조건 충족 여부 확인· 테스트 담당자 — 인수 기준 및 테스트 케이스 도출 근거로 사용
1.2 프로젝트 범위 (Scope)
[해결하려는 문제]서면·남포동·해운대 등 부산 도심은 주차 수요가 집중되어, 운전자가 목적지에 도착한 뒤에야 빈자리 유무와 요금을 알게 되고 주변을 배회하는 경우가 많다. 기존 지도 서비스는 '가까운 주차장'은 보여주지만, "서면에서 3시간 주차할 건데 지금 자리 있고 요금도 싼 곳"과 같이 목적지·주차 예상 시간·예산·실시간 빈자리가 결합된 조건을 한 번에 처리하지 못한다
[제공하는 핵심 서비스]1. 자연어 질의 해석 — LLM을 활용하여 사용자의 입력에서 목적지, 예상 주차 시간, 예산 상한을 추출하고 구조화된 검색 조건으로 변환한다2. 주차장 검색 — 공공데이터 기반 부산 공영주차장의 위치·요금·운영시간 조회3. 실시간 혼잡도 반영 — 부산시설공단 제공 실시간 주차 가능 대수 조회4. 맞춤 추천 — 목적지와의 직선거리, 예상 주차 요금, 주차 가능 여부를 고려하여 적합한 주차장을 추천한다. 초기 버전은 만차가 확인된 주차장과 예산 초과 주차장을 제외한 후 직선거리가 가까운 순서대로 추천 결과를 제공한다.5. 지도 연동 — 추천 결과의 지도 표시 및 외부 길찾기 연결
[범위 제외 항목]· 실제 주차 예약 및 결제 기능· 민영 주차장의 실시간 잔여 면수 (공개 API 미제공)· 차량 번호 인식, 출차 알림, 주차 시간 자동 측정

2. 전체 설명 (Overall Description)
2.1 제품 관점 (Product Perspective)
본 서비스는 부산 지역의 공영주차장 정보를 제공하는 독립형 모바일 애플리케이션이다. 사용자는 모바일 기기를 통해 자연어 기반 주차장 검색, 맞춤형 주차장 추천, 지도 기반 위치 확인 및 외부 지도 서비스 연동 기능을 이용할 수 있다. 시스템은 외부 공공데이터 API, 지도 API 및 LLM API를 활용하며, 주차장 데이터 조회와 추천 기능은 백엔드 서버를 통해 처리한다.· 정적 데이터(주차장 위치·요금·운영시간)는 공공데이터를 주기적으로 수집해 자체 데이터베이스에 적재한 뒤 서비스 내부에서 조회한다.· 실시간 데이터(잔여 면수)는 질의 시점에 외부 API를 호출하고, 동일 조건에 대해 단기 캐시를 적용한다.· 지도 표시·지오코딩·길찾기는 외부 지도 API를 연동한다.· 자연어 해석은 외부 LLM API를 호출하되, 수치 정보는 모델이 생성하지 않고 조회된 데이터만 사용한다.

2.4 제약사항 (Constraints)
부산광역시 공영주차장을 서비스 대상으로 하며, 실제 주차 예약 및 결제 기능은 개발 범위에서 제외한다.
실시간 잔여 면수는 제공기관이 공개하는 주차장에 한정되며, 갱신 주기와 제공 범위는 해당 기관의 정책을 따른다.
데이터셋 간 주차장 식별자가 일치하지 않을 수 있으므로, 명칭·주소·좌표를 통한 매칭이 필요하다.
LLM 단독 응답으로 서비스를 구성하지 않으며, 실제 데이터 조회와 규칙 기반 계산을 연계해야 한다.
공공데이터·지도·AI 서비스의 이용조건을 준수하고, 사용한 데이터의 출처를 명시해야 한다.
일반 사용자는 회원가입 없이 이용하며, 개인정보 수집과 저장을 최소화한다.
외부 서비스는 확보한 무료 쿼터와 API 호출한도 내에서 사용한다.
해당 학기 내에 개발과 검증을 완료해야 한다.
모바일 운영체제의 권한 정책과 외부 지도 서비스의 앱 연동 정책을 준수해야 하며, 외부 API의 이용 한도 및 데이터 제공 범위를 고려하여 기능을 구현한다
2.5 가정 및 의존성 (Assumptions &amp; Dependencies)
공공데이터포털 및 부산시설공단이 제공하는 주차장 데이터·API가 과제 수행 기간 중 정상 제공된다고 가정한다.
실시간 잔여 면수의 갱신 주기는 제공기관 정책을 따르며, 본 서비스가 이를 단축할 수 없다. 따라서 화면에는 항상 '최종 갱신 시각'을 함께 표시한다.
외부 LLM API와 지도 API가 무료 또는 팀이 확보한 쿼터 범위에서 이용 가능하다고 가정한다.
사용자는 위치 권한을 허용하지 않을 수 있으므로, 목적지를 직접 입력하는 경로가 항상 제공되어야 한다.

5.2 Use Case 명세
Use Case ID
UC-001
이름
자연어 주차장 추천 질의
Actor
운전자(일반 사용자)
사전조건
사용자가 서비스 메인 화면에 접속한 상태이다. 시스템은 자연어 검색 기능을 사용할 수 있어야 한다
트리거
사용자가 목적지, 주차 시간, 예산 등을 포함한 자연어 질의를 입력하고 검색을 요청한다.
기본 흐름
1. 사용자가 자연어로 주차장 추천 질의를 입력한다.2. 시스템은 LLM을 이용하여 질의에서 목적지, 예상 주차 시간, 최대 예산을 추출한다.3. 시스템은 사용자가 확인할 수 있도록 추출된 조건을 표시한다. 4. 시스템은 목적지 좌표를 확보한다.5. 시스템은 목적지 주변의 주차장 기본 정보와 요금 정보를 조회한다.6. 시스템은 실시간 데이터가 제공되는 경우 주차 가능 대수와 갱신 시각을 조회한다.7. 시스템은 예상 주차 요금을 계산한다.8. 시스템은 만차 여부, 예산 조건, 거리 등을 기준으로 주차장 후보를 정렬한다.9. 시스템은 추천 결과 목록을 사용자에게 표시한다. AI 추천 이유 생성 기능이 활성화된 경우 조회된 주차장 정보를 근거로 추천 이유를 함께 표시한다.
대안/예외 흐름
2a. LLM이 목적지를 추출하지 못한 경우 → 시스템은 목적지를 다시 입력하도록 요청한다. 4a. 목적지 검색 결과가 2개 이상인 경우 → 시스템은 후보 목록을 제시하고 사용자가 선택한다. 5a. 자체 데이터베이스 조회에 실패한 경우 → 시스템은 주차장 정보 조회 실패를 안내하고 검색을 종료한다.6a. 실시간 주차 정보 API 호출에 실패한 경우 → 시스템은 정적 주차장 정보를 유지하며 실시간 주차 가능 여부를 '확인 불가'로 표시한다.7a. 요금 계산에 필요한 정보가 부족한 경우 → 시스템은 ‘요금 계산 불가’로 표시한다. 8a.검색 조건을 만족하는 주차장이 없는 경우 → 시스템은 검색 결과 없음 메시지를 표시한다.
사후조건
사용자는 조건에 맞는 주차장 추천 목록과 요약 정보를 확인할 수 있다.

사전조건
UC-001이 1회 이상 수행되어 추천 결과가 화면에 표시된 상태이다.
트리거
사용자가 “더 싼 곳”, “조금 더 가까운 곳”, “2시간 기준으로 다시”와 같은 후속 자연어 질의를 입력한다.
기본 흐름
1. 사용자가 후속 자연어 질의를 입력한다. 2. 시스템은 이전 검색 조건을 불러온다. 3. 시스템은 후속 질의에서 변경된 조건을 분석한다. 4. 시스템은 기존 조건에 변경된 조건만 반영한다.5. 시스템은 수정된 조건에 따라 주차장 정보를 다시 조회하거나 재정렬한다. 6. 시스템은 갱신된 추천 결과와 반영된 조건을 함께 표시한다.
대안/예외 흐름
2a. 이전 검색 결과가 없거나 세션이 만료된 경우 → 시스템은 처음부터 다시 검색하도록 안내한다. 3a. 후속 질의의 의미를 해석하지 못한 경우 → 시스템은 변경할 조건을 다시 입력하도록 요청한다. 5a. 수정된 조건을 만족하는 결과가 없는 경우 → 시스템은 조건 완화를 제안한다.
사후조건
사용자는 처음 조건을 반복 입력하지 않고도 수정된 조건이 반영된 추천 결과를 확인할 수 있다.

기본 흐름
1. 사용자가 지도 보기 기능을 선택한다. 2. 시스템은 목적지와 추천 주차장들의 좌표 정보를 불러온다. 3. 시스템은 지도 API를 이용하여 목적지와 주차장 위치를 지도에 마커로 표시한다. 4. 시스템은 사용자가 선택한 주차장의 요약 정보를 지도와 함께 표시한다.
대안/예외 흐름
2a. 좌표 정보가 없는 주차장이 있는 경우 → 시스템은 해당 주차장을 지도에 표시하지 않고 목록에서만 제공한다. 3a. 지도 API 호출이 실패한 경우 → 시스템은 지도 표시 실패 메시지를 안내하고 목록 보기로 유지한다.
사후조건
사용자는 추천 주차장과 목적지의 상대적 위치를 지도에서 확인할 수 있다.

사용자가 목적지, 주차 예정 시간, 예산 등의 조건을 자연어 문장으로 입력할 수 있어야 한다.
FR-001
Acceptance Test
AC-002
자연어 검색 시 LLM이 목적지, 주차 예정 시간, 최대 예산을 추출하여 구조화된 검색 조건으로 변환해야 한다.
FR-002
AI Evaluation
AC-003
사용자가 AI가 분석한 검색 조건을 확인하고 목적지, 주차 예정 시간, 최대 예산을 각각 수정할 수 있어야 한다.
FR-003
Acceptance Test
AC-004
부산 지역의 목적지를 검색하고 사용자가 선택한 목적지의 위도와 경도를 확보할 수 있어야 한다.
FR-004
API Test
AC-005
선택한 목적지로부터 직선거리 2km 이내에 위치한 주차장만 검색 결과에 포함되어야 한다.
FR-005
Integration Test
AC-006
검색된 주차장의 이름, 주소, 목적지와의 직선거리가 목록에 표시되어야 한다.
FR-006
UI Test
AC-007
주차장 선택 시 주소, 운영시간, 요금 정책 등 확보된 상세 정보를 확인할 수 있어야 한다.
FR-007
Acceptance Test
AC-008
주차 예정 시간과 주차장 요금 정책을 기반으로 예상 요금이 계산되어야 하며, 계산에 필요한 정보가 부족한 경우 '요금 계산 불가'로 표시되어야 한다.
FR-008
Unit Test
AC-009
최대 예산을 초과하는 주차장은 추천 대상에서 제외되어야 하며, 요금 계산이 불가능한 주차장은 별도로 구분되어야 한다.
FR-009
Functional Test
AC-010
실시간 정보가 제공되는 주차장의 주차 가능 대수와 마지막 데이터 갱신 시각이 표시되어야 한다.
FR-010
API Test
AC-011
요금, 운영시간, 주차 가능 대수 등의 데이터가 누락된 경우 해당 항목이 '확인 불가' 또는 '정보 없음'으로 표시되어야 한다.
FR-011
Exception Test
AC-012
확인된 만차 주차장과 예산 초과 주차장은 추천에서 제외되고, 나머지 추천 대상은 직선거리 오름차순으로 정렬되어야 한다. 거리가 동일하면 예상 요금이 낮은 주차장이 우선해야 한다.
FR-012
Algorithm Test
AC-013
추천된 주차장의 거리, 요금, 주차 가능 정보를 근거로 LLM이 생성한 추천 이유가 표시되어야 한다.
FR-013
AI Evaluation
AC-014
선택한 목적지와 검색된 주차장의 위치가 지도에 각각 마커로 표시되어야 한다.
FR-014
UI Test
AC-015
사용자가 길찾기 기능을 선택하면 해당 주차장이 목적지로 지정된 외부 지도 서비스의 길찾기 화면으로 연결되어야 한다.
FR-015
Integration Test
AC-016
검색 조건을 만족하는 주차장이 없는 경우 '검색 조건에 맞는 주차장이 없습니다'라는 메시지가 표시되어야 한다.
FR-016
Exception Test
AC-017
실시간 주차 현황 API 호출에 실패한 경우 해당 주차장의 주차 가능 정보를 '확인 불가'로 표시하고 사용자에게 실시간 정보 조회 실패를 안내해야 한다. 이때 자체 데이터베이스에 저장된 주차장 기본 정보, 운영시간 및 요금 정보는 정상적으로 제공되어야 한다.
FR-017
Exception Test
AC-018
LLM API 호출에 실패한 경우 오류를 안내하고 목적지, 주차 시간, 예산을 직접 입력할 수 있는 검색 화면이 제공되어야 한다.
FR-018
Exception Test
AC-019
이전 검색 결과가 존재하는 상태에서 사용자가 주차 예정 시간 또는 최대 예산을 변경하는 후속 질의를 입력하면, 변경하지 않은 조건은 유지되고 변경된 조건이 추천 결과에 반영되어야 한다.
FR-019
Acceptance Test
